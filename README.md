# Универсальный Telegram-конструктор

Конструктор сценариев без кода: пользователь собирает страницы, добавляет текст и кнопки переходов, а затем публикует сценарий по ссылке.

> **Важно:** это один общий Telegram-бот. Пользовательские сценарии работают внутри него; создание отдельного Telegram-бота каждому пользователю не поддерживается.

## Возможности

- Создание сценария и редактирование его названия.
- Создание произвольного количества страниц и редактирование их названий и текста.
- Добавление нескольких кнопок на страницу; каждая кнопка ведёт на выбранную страницу.
- Удаление страниц, кнопок и сценариев с подтверждением.
- Публикация сценария и запуск по ссылке `https://t.me/<bot_username>?start=flow_<project_id>`.
- Хранение проектов в SQLite.
- Раздельное управление сценариями по Telegram ID владельца.

## Быстрый запуск

### 1. Создайте Telegram-бота

Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot` и сохраните выданный токен. Не публикуйте и не отправляйте токен в репозиторий.

### 2. Настройте проект

Нужен Python 3.10 или новее.

**Windows PowerShell:**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и задайте `BOT_TOKEN`.

**Linux/macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и задайте `BOT_TOKEN`.

### 3. Запустите бота

```bash
python main.py
```

Откройте созданного бота в Telegram и нажмите **Start**. Процесс нужно оставить запущенным. SQLite-файл по умолчанию создаётся в `data/bot.sqlite3`.

## Использование

1. В меню выберите **Создать сценарий** и введите его название.
2. Отправьте текст стартовой страницы.
3. Откройте сценарий, нажмите **Добавить страницу**, введите название и текст. Повторите для остальных страниц.
4. Откройте нужную страницу, нажмите **Добавить кнопку перехода** и укажите подпись. Выберите существующую страницу или нажмите **Создать страницу** — новая страница будет автоматически назначена целью кнопки.
5. Опубликуйте сценарий и получите ссылку в его меню.

В меню сценария можно изменить название, снять сценарий с публикации или удалить его. В меню страницы можно изменить название и текст, добавить или удалить кнопки, а также удалить страницу. Стартовую страницу удалить нельзя. Удаление страницы удаляет и все переходы на неё и с неё.

Незавершённый ввод отменяется командой `/cancel`.

## Конфигурация

| Переменная | Обязательная | Значение по умолчанию | Описание |
|---|---:|---|---|
| `BOT_TOKEN` | Да | — | Токен бота от @BotFather |
| `BOT_DB_PATH` | Нет | `data/bot.sqlite3` | Путь к файлу SQLite |

Настройки можно задавать в `.env` или переменных окружения процесса. Пример находится в [.env.example](.env.example).


## Публикация в GitHub

Локальный Git-репозиторий уже инициализирован на ветке `main`. Чтобы опубликовать его:

1. Создайте на GitHub **пустой** репозиторий — не добавляйте при создании README, лицензию или `.gitignore`.
2. Убедитесь, что `.env` не попадёт в коммит:

   ```bash
   git check-ignore -v .env data/bot.sqlite3
   git status --short
   ```

3. Создайте первый коммит:

   ```bash
   git commit -m "Prepare universal Telegram bot builder"
   ```

4. Добавьте URL созданного репозитория и отправьте ветку:

   ```bash
   git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
   git push -u origin main
   ```

Если GitHub попросит авторизацию, используйте настроенный Git Credential Manager или SSH-ключ; не вставляйте токены в URL репозитория.

## Запуск в Docker

1. Установите Docker Compose.
2. Создайте `.env` из `.env.example` и укажите `BOT_TOKEN`.
3. Запустите контейнер:

   ```bash
   docker compose up -d --build
   ```

4. Посмотрите журнал:

   ```bash
   docker compose logs -f
   ```

5. Остановите:

   ```bash
   docker compose down
   ```

Данные SQLite сохраняются в Docker volume `bot_data` и переживают пересоздание контейнера. Для подробностей и резервного копирования см. [руководство по развёртыванию](docs/DEPLOYMENT.md).

## Безопасность и ограничения

- Никогда не коммитьте `.env`, токен бота или файл базы данных.
- Токен даёт управление ботом. При утечке отзовите его через @BotFather и задайте новый.
- Публичный сценарий может открыть любой пользователь Telegram, знающий ссылку.
- Снятие с публикации запрещает дальнейший запуск по ссылке; удаление сценария необратимо.
- Незавершённое состояние диалога хранится в памяти и теряется при перезапуске; сохранённые сценарии остаются в SQLite.
- В первой версии нет медиафайлов, условий, аналитики, веб-редактора и переноса страниц.
