# Развёртывание и обслуживание

## Подготовка

1. Создайте бота через @BotFather.
2. Установите Python 3.10+ или Docker с Docker Compose.
3. Создайте локальный `.env` на основе `.env.example`.
4. Установите `BOT_TOKEN`; при необходимости задайте `BOT_DB_PATH`.

Не добавляйте `.env` в Git и не помещайте токен в Dockerfile, Compose-файл или команду, которая попадёт в историю shell.

## Запуск Python-процесса

```bash
python -m venv .venv
python -m pip install -r requirements.txt
python main.py
```

Для production бот должен работать под менеджером процессов или оркестратором, который перезапускает процесс после сбоя. Не запускайте несколько polling-процессов с одним токеном.

## Запуск Docker Compose

```bash
docker compose up -d --build
docker compose logs -f
```

Сервис читает `.env`; постоянная база хранится в именованном томе `bot_data`. Для обновления кода пересоберите и перезапустите контейнер:

```bash
docker compose up -d --build
```

Для остановки:

```bash
docker compose down
```

Команда `docker compose down -v` удалит volume с базой данных. Не используйте её, если данные нужно сохранить.

## Резервное копирование

Остановите контейнер или процесс перед копированием SQLite-файла, чтобы получить согласованную резервную копию.

В Docker можно скопировать базу из работающего контейнера:

```bash
docker compose cp bot:/app/data/bot.sqlite3 ./bot-backup.sqlite3
```

Храните резервные копии отдельно от Git и ограничивайте к ним доступ: в базе находятся пользовательские сценарии.

Для восстановления остановите бота, замените файл в постоянном хранилище и запустите приложение снова.

## Обновление токена

Если токен был опубликован или передан посторонним:

1. Отзовите его в @BotFather и выпустите новый.
2. Обновите `BOT_TOKEN` в `.env` или секретах окружения.
3. Перезапустите процесс/контейнер.
4. Проверьте журнал запуска и работу `/start`.

## Журналы и диагностика

Для Docker:

```bash
docker compose logs --tail=100
```

Приложение пишет журнал в stdout. Не включайте в диагностические сообщения содержимое `.env` или токен.

## GitHub Actions

Workflow `.github/workflows/tests.yml` устанавливает зависимости, запускает `unittest` и проверяет компиляцию на Python 3.10–3.13 при push и pull request. Секреты Telegram в CI не требуются.
